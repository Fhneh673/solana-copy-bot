# Solana Copy Bot

Бот следит за кошельками опытных трейдеров в Solana. Когда такой кошелёк покупает или продаёт токен, бот повторяет сделку на вашем кошельке — с вашим размером и вашей защитой.

> ⚠ **Важно.** Копитрейдинг — это риск потерять деньги. Бот всегда повторяет сделку с задержкой, цена к этому моменту может быть хуже, а часть токенов оказывается мусором. Начните с **тестового режима** (деньги не тратятся), потом переходите на реальный с небольшой суммой и **отдельным кошельком**.

---

## Быстрый старт (3 шага)

**1. Установите Python** (один раз): https://www.python.org/downloads/ — на Windows при установке отметьте галочку **Add Python to PATH**.

**2. Запустите бота**
- Windows: два раза нажмите **`start.bat`**
- Mac / Linux: в терминале `bash start.sh`

При первом запуске он сам поставит всё нужное и откроет **мастер настройки** — просто отвечайте на вопросы. Если не уверены, жмите Enter: значения по умолчанию безопасные.

**3. Готово.** Бот покажет, что он будет делать, проверит подключения (✓ / ✗) и начнёт работать. Остановить — `Ctrl+C`.

Позже:
| Что нужно | Windows | Mac / Linux |
|---|---|---|
| Запустить | `start.bat` | `bash start.sh` |
| Изменить настройки | `start.bat setup` | `bash start.sh setup` |
| Только проверить подключения | `start.bat check` | `bash start.sh check` |

## Что понадобится

1. **Ссылка RPC** — «окно» в сеть Solana. Возьмите бесплатную на [helius.dev](https://www.helius.dev): создать аккаунт → создать ключ → скопировать ссылку вида `https://mainnet.helius-rpc.com/?api-key=...`. Публичный RPC по умолчанию медленный и часто не подходит.
2. **Адреса кошельков**, за которыми следим. Их можно взять в обозревателях и трекерах Solana (разделы про топ-трейдеров), а также у самих трейдеров, которые публикуют свои кошельки. Проверяйте историю кошелька сами: чужая прибыль в прошлом ничего не гарантирует.
3. **Для реального режима** — отдельный кошелёк с небольшой суммой SOL и его приватный ключ (в формате base58, как экспортирует Phantom). Ключ сохраняется только в файле `.env` на вашем компьютере.

## Что означают настройки

Все настройки задаёт мастер. Потом их можно править вручную в `config.json`.

**Сколько копировать** (`sizing.mode`)

| Вариант | Как работает | Пример |
|---|---|---|
| `ratio` — доля от его сделки | Он вложил 2 SOL, у вас `ratio` 0.1 → вы вложите 0.2 SOL. Значение 1 — «один в один», 2 — вдвое больше | `"ratio": 0.1` |
| `fixed` — фиксированная сумма | Всегда одна и та же сумма | `"fixed_sol": 0.1` |
| `percent_balance` — % от баланса | Процент от вашего свободного баланса | `"percent": 2` |

**Защита** (`risk`) — значение `0` выключает пункт (в том числе `max_sol_per_trade`, `max_position_pct`, `max_open_positions`)

| Настройка | Простыми словами |
|---|---|
| `max_sol_per_trade` | Не больше стольки SOL за одну покупку |
| `max_position_pct` | Не больше такого % капитала в одной монете |
| `max_open_positions` | Не больше стольких монет одновременно |
| `stop_loss_pct` | Если позиция упала на столько % — продать всё |
| `take_profit_pct` | Если позиция выросла на столько % — зафиксировать часть |
| `tp_sell_fraction` | Какую часть продавать при тейк-профите (0.5 = половину) |
| `max_drawdown_pct` | Если весь портфель потерял столько % от стартового — перестать покупать |
| `on_drawdown` | `stop` — только не покупать новое, `close_all` — ещё и продать всё |
| `min_sol_reserve` | Сколько SOL всегда оставлять на комиссии |

**Jupiter.** Адрес `lite-api.jup.ag` Jupiter объявил устаревшим (срок отключения переносился, новая дата не названа). Получите бесплатный ключ на [portal.jup.ag](https://portal.jup.ag) и добавьте в `.env` строку `JUPITER_API_KEY=...` (или `jupiter_api_key` в `config.json`). Тогда бот сам перейдёт на `https://api.jup.ag/swap/v1` и будет слать заголовок `x-api-key`. Без ключа используется lite-api. Учтите лимит запросов вашего тарифа: монитор запрашивает котировку по каждой позиции каждые `check_interval_sec` секунд.

**Прочее:** `min_target_sol` — игнорировать покупки цели меньше этой суммы (по умолчанию 0.5 SOL); `slippage_bps` — допустимое проскальзывание (300 = 3%); `max_price_impact_pct` — не входить, если сделка слишком сильно двигает цену; `blacklist` — токены, которые копировать нельзя.

## Как читать вывод

```
Что будет делать бот:
  Режим: ТЕСТ — реальные деньги НЕ тратятся...
  Когда кошелёк ПОКУПАЕТ токен, я покупаю на: 10% от суммы, которую вложил он
  ...
Проверяю подключения…
  ✓ RPC отвечает
  ✓ WebSocket работает (слежение за кошельками)
  ✓ Jupiter даёт котировки
```
Дальше в ходе работы:

| Строка | Смысл |
|---|---|
| `цель 7xKX..: buy ABC123 на 2.000 SOL` | Отслеживаемый кошелёк купил токен |
| `BUY ABC123 на 0.2000 SOL` | Бот повторил покупку |
| `SELL ABC123 100% [продажа цели ..]` | Бот продал вслед за целью |
| `SELL ... [STOP-LOSS -31.0%]` | Сработал стоп-лосс |
| `SELL ... [TAKE-PROFIT +105.0%]` | Сработал тейк-профит |
| `equity=... просадка=...%` | Раз в несколько секунд: капитал и общая просадка |
| `ЛИМИТ ПРОСАДКИ ... копирование остановлено` | Сработала защита портфеля; новые покупки отключены |
| `skip: ...` | Бот сознательно пропустил сделку и написал почему |

Позиции и статистика сохраняются в `state.json`, поэтому перезапуск ничего не теряет.

## Возможности

**Копирование**
- Несколько кошельков; у каждого можно задать **имя и свои настройки** (`ratio`, `fixed_sol`, `max_sol_per_trade`, `enabled`) в `config.json`.
- Размер сделки: доля от его сделки / фиксированная сумма / % от баланса.
- Вслед за целью бот продаёт ту же долю. По умолчанию `sell_follow: owner`: продаём вслед только тому кошельку, который открыл позицию (если другой кошелёк продаёт тот же токен, бот не реагирует).

**Защита от скама и плохих входов** (раздел `filters`, включено по умолчанию)
- не покупает токен, у которого создатель может **допечатать** (mint authority) или **заморозить** ваши токены (freeze authority);
- проверяет, что токен **можно продать**, и что круг «купил-продал» по текущим котировкам не съест больше `max_roundtrip_loss_pct` (по умолчанию 35%);
- **не покупает, если цена уже хуже цены цели** больше чем на `max_price_deviation_pct` (по умолчанию 20%): так бот не залетает на пик после чужой покупки.

Эти проверки добавляют доли секунды к каждой покупке и не дают 100% гарантии: они ловят типичные ловушки, но не всё. Отключить: `"filters": {"enabled": false}`. Токены из `whitelist_mints` проверок не проходят.

**Выход из позиции** (раздел `risk`)
- `stop_loss_pct` — стоп-лосс;
- `take_profit_levels` — **лесенка** тейк-профита, например `[{"pnl_pct": 50, "sell_pct": 30}, {"pnl_pct": 100, "sell_pct": 40}]` (`sell_pct` считается от размера входа);
- `trailing_stop_pct` и `trailing_activate_pct` — **трейлинг-стоп**: после роста на `trailing_activate_pct`% продаём, если цена откатила от максимума на `trailing_stop_pct`%;
- `max_hold_minutes` — закрыть позицию, если держим дольше;
- `max_drawdown_pct` и `on_drawdown` — защита всего портфеля.

**Умные кошельки**
- Бот ведёт статистику по каждому кошельку (сделки, доля прибыльных, итог в SOL; команда `/wallets`).
- `wallet_max_consecutive_losses` и `wallet_max_loss_sol` автоматически ставят на **паузу** кошелёк, который приносит убытки. Вернуть: `/wallet resume <имя>`.

**Журнал и отчёты**
- Каждая сделка пишется в `trades.csv` (открывается в Excel / Google Sheets): время, действие, причина, кошелёк, токен, сумма, результат, ссылка на транзакцию.

**Telegram** (по желанию, подключается в мастере настройки)
- Уведомления: покупка, продажа (с результатом), срабатывание стопов, пауза кошелька, лимит просадки.
- Команды (только из вашего чата и только от вашего пользователя; для группового чата перечислите `telegram.allowed_user_ids`): `/status`, `/positions`, `/wallets`, `/stats`, `/pause`, `/resume`, `/rebase`, `/wallet pause|resume <имя>`, `/close <начало адреса токена>`, `/closeall ДА`, `/help`. Старые сообщения, накопившиеся до запуска, игнорируются.
- Токен бота и chat_id хранятся в `.env`.

**Скорость**
- Быстрое ядро на Rust (раздел ниже), параллельная отправка на несколько RPC (`send_rpcs`).
- **Jito** (по желанию): `"jito": {"enabled": true, "tip_lamports": 100000}` добавляет чаевые валидаторам и дублирует отправку в Jito. Функция не проверена на реальной сети: сначала проверьте её с минимальными суммами.
- Бот ждёт **подтверждения** транзакции в сети. Если подтверждение не пришло за `confirm_timeout_sec`, покупка не считается неудачной: она запоминается (`pending` в `state.json`) и сверяется с сетью, пока не станет ясно, прошла ли она. При старте бот сверяет кошелёк и берёт под защиту токены, которых нет в учёте (`adopt_unknown_tokens`, по умолчанию включено; поэтому кошелёк бота должен быть отдельным).
- Результат сделок считается **по факту исполнения** (баланс кошелька до/после, с комиссиями, чаевыми и арендой токен-аккаунта), а не по котировке. Стоп-лосс и тейк-профит по-прежнему смотрят на цену токена.
- Выход из позиции (стоп-лосс, `/close`, `/closeall`) **не ограничивается** `max_price_impact_pct`: лимит действует только на покупки. Сбой продажи одной позиции не мешает защите остальных, неудачные продажи повторяются каждый цикл.
- Токен без маршрута продажи `no_route_cycles` проверок подряд (по умолчанию 3) оценивается в 0 SOL, чтобы просадка и стоп-лосс отражали реальность.
- После обрыва WebSocket бот **догоняет** пропущенные сделки целей (покупки старше 60 с не копируются).
- Пополнение или вывод SOL, сделанные без участия бота, корректируют стартовый капитал автоматически (и вручную: `/rebase`).
- `state.json` помнит режим (тест/реальный). Если режим сменился и в состоянии есть позиции, бот откажется стартовать; без позиций начнёт отсчёт капитала заново.

## Режим Rust (быстрое ядро)

Бот гибридный: всё, где важна скорость, работает в ядре на **Rust**, а решения (размер сделки, лимиты, стоп-лосс, просадка) принимает **Python**.

| Делает ядро Rust | Делает Python |
|---|---|
| Слежение за кошельками по WebSocket | Настройки, мастер, проверки |
| Разбор сделки цели | Размер входа и лимиты |
| Котировки Jupiter, подпись и отправка транзакции | Стоп-лосс, тейк-профит, лимит просадки |
| Ожидание подтверждения в сети | Состояние (`state.json`), логи |

Что ускоряет ядро: постоянные «тёплые» соединения с RPC и Jupiter (без повторных рукопожатий), параллельная отправка на несколько RPC (`send_rpcs`), подпись без Python и контроль подтверждения. Ядро пишет в лог, за сколько миллисекунд оно заметило сделку цели и исполнило вашу, так что эффект можно измерить.

**Как включить.** Нужен [Rust](https://rustup.rs) (один раз). Дальше `start.bat` / `start.sh` сами соберут ядро при первом запуске (2–5 минут). Вручную: `build_core.bat` / `bash build_core.sh`, принудительная пересборка (бота не запускает): `start.bat build` / `bash start.sh build`.

**Если Rust не установлен или сборка не удалась**, бот просто работает на Python-движке. А если ядро упадёт во время работы, бот сам переключится на Python и продолжит.

Для сборки на Windows нужны Visual Studio Build Tools (установщик Rust предложит их сам). Если сборка падает на `aws-lc-sys`, поставьте CMake (cmake.org) и повторите.

Проверить код ядра без запуска: `cd core && cargo check`, юнит-тесты (разбор свопа и подпись): `cargo test`. После первой сборки закоммитьте появившийся `core/Cargo.lock`, чтобы сборка была воспроизводимой.

Параметр `engine` в `config.json`: `auto` (по умолчанию: Rust, если собран), `rust` (только Rust, иначе ошибка), `python` (всегда Python). Дополнительно: `send_rpcs` — список дополнительных RPC-ссылок для параллельной отправки, `confirm_timeout_sec` — сколько ждать подтверждения транзакции.

Чтобы отдать бота заказчику без установки Rust, соберите ядро на каждой нужной ОС и положите готовый файл в папку `bin/`.

## Частые вопросы

**Бот пишет «неизвестная настройка».** Настройки проверяются строго: опечатка или значение не того типа остановят запуск с подсказкой, какой ключ имелся в виду.

**Бот ничего не покупает.** Это нормально, если цель давно не торговала. В логе должны быть строки `цель ...`. Если их нет — проверьте `start.bat check` (особенно WebSocket) и адреса кошельков.

**`✗ WebSocket не подключился`.** Почти всегда дело в публичном RPC. Возьмите бесплатный ключ Helius и запустите `start.bat setup`.

**Бот пишет `skip: ...` и не копирует.** Причина указана в строке: размер меньше минимума, сработал лимит, токен уже есть, достигнут максимум позиций и т.д.

**Копирование остановилось (просадка).** Сработала защита портфеля. Чтобы продолжить, отправьте боту в Telegram `/resume ДА` (отсчёт просадки начнётся заново) или откройте `state.json`, поставьте `"halted": false` (или запустите настройку заново и согласитесь начать с чистого листа).

**Как перейти из теста в реальный режим?** `start.bat setup` → в шаге 7 выберите 2. Бот ещё раз спросит подтверждение перед стартом.

**Какие сделки бот понимает?** Простые обмены SOL ↔ один токен. Сделки через стейблкоины и сложные цепочки он пропускает.

**Ограничения.** Если продажа отправлена, но подтверждение не пришло за таймаут, записанный размер позиции поправится только при следующей успешной продаже, а до этого оценка позиции может быть завышена (у покупок такой проблемы нет: они сверяются через `pending`). Торговая логика проверена офлайн на моках, но не на реальных деньгах в mainnet: начинайте с минимальных сумм. Позиции проверяются на стоп-лосс и тейк-профит раз в несколько секунд, поэтому на очень быстрых монетах цена может «проскочить» стоп. Если у токена пропала ликвидность, продать его не получится.

## Для разработчиков

```
main.py              запуск (+ --check)
setup_wizard.py      мастер настройки
start.bat / start.sh запуск «в один клик» (создаёт .venv, ставит зависимости, собирает ядро)
build_core.bat / .sh сборка ядра Rust -> bin/
core/                ядро на Rust (Cargo.toml, src/: watcher, parser, exec, wallet, rpc)
tests/               pytest-тесты (запуск: `pytest tests/` или `python tests/test_risk.py`): риск и торговля, Jupiter, parser, config, Telegram, Rust-гибрид + mock_core.py
config.example.json  полный пример настроек
copybot/
  config.py          загрузка, проверка, описание настроек
  preflight.py       проверка подключений перед стартом
  trader.py          оркестратор: copy / close
  engine/            rust_engine.py (процесс ядра, JSON по stdin/stdout), python_engine.py (запасной)
  chain/             rpc.py, jupiter.py, watcher.py (Python-версии), wallet.py
  strategy/          parser.py (разбор свопа), sizing.py (режимы размера)
  risk/              limits.py (лимиты), monitor.py (SL / TP / просадка)
  storage/           state.py (state.json), journal.py (trades.csv)
  notify/            telegram.py (уведомления и команды)
  control.py         команды управления (/status, /pause, /closeall …)
  risk/filters.py    фильтры токенов перед покупкой
```

Протокол ядра (JSON, по строке на сообщение). Python → ядро: `init`, `quote`, `swap`, `shutdown`. Ядро → Python: `ready`, `swap` (сделка цели), `res` (ответ на команду), `log`. Приватный ключ ядро берёт из переменной окружения `PRIVATE_KEY`, по каналу он не передаётся.
